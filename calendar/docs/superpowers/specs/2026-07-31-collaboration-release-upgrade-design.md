# 협업 발매 캘린더 업그레이드 설계

## 목표

현재 발매달력을 스니커즈 중심 일정표에서 국내 한정 발매와 패션·라이프스타일 협업까지 다루는 캘린더로 확장한다. 외부 판매처 트래픽은 사용자 수와 분리하고, 공식 출처 중심의 자동 수집과 예외 검수로 운영 부담을 최소화한다.

## 성공 기준

- 사용자 접속이 외부 판매처 재수집을 유발하지 않는다.
- 외부 수집은 Asia/Seoul 기준 하루 5회만 실행된다.
- Salomon Korea, ASICS Korea, TUNE의 공식 일정이 기존 소스와 함께 표시된다.
- 협업·래플·오프라인 한정 일정을 빠르게 구분할 수 있다.
- 중복 일정은 하나의 상품과 여러 판매처로 통합된다.
- 공식 정보가 충돌하거나 불완전한 항목만 관리자 검수함에 나타난다.
- 한 판매처가 실패해도 마지막 정상 데이터와 다른 판매처 일정은 계속 제공된다.

## 수집 일정

수집 시각은 매일 07:30, 09:30, 13:00, 18:00, 22:30이다. 사용자가 페이지를 열 때는 D1의 저장 결과만 조회한다. 관리자 수동 수집은 전체가 아니라 선택한 판매처 하나에 대해서만 실행한다.

## 소스 범위

### 기존 소스

Nike, Adidas, Shoeprize, ABC Grandstage, New Balance, Musinsa, Soldout, Worksout, Kasina, KREAM, Converse, Fila를 유지한다.

### 1차 신규 소스

- Salomon Korea의 런칭 캘린더와 래플 이벤트
- ASICS Korea의 Launch Calendar
- TUNE의 발매 상품과 응모 일정

### 안정성 확인 후 추가

- Kith Seoul News
- EQL
- On The Spot

Kith Seoul, EQL, On The Spot은 전용 일정 구조와 중복률을 먼저 측정한 뒤 활성화한다.

### 후속 범위

Instagram을 포함한 SNS 수집은 이번 구현에 포함하지 않는다. 운영용 Instagram Business 또는 Creator 계정, Facebook Page, Meta 앱 권한을 준비한 뒤 별도 설계·구현한다.

## 수집 구조

각 판매처 어댑터는 원본 데이터를 공통 `CollectedRelease` 형식으로 변환한다. 예약 수집기는 판매처별 결과를 저장하고, 정규화·중복 판정·변경 감지를 거쳐 공개 일정 또는 검수 후보로 분류한다.

```ts
type CollectedRelease = {
  sourceKey: string;
  externalId: string;
  title: string;
  brand: string | null;
  category: "sneakers" | "fashion" | "lifestyle";
  releaseKind: "general" | "collab" | "raffle" | "offline";
  releaseDate: string;
  releaseTime: string | null;
  priceLabel: string | null;
  styleCode: string | null;
  retailer: string;
  productUrl: string;
  sourceUrl: string;
  collectedAt: string;
};
```

어댑터는 한 판매처의 수집과 파싱만 담당한다. 예약 실행, 저장, 중복 제거, 검수 판정과 UI 표시 로직을 어댑터에 넣지 않는다.

## 데이터 저장

D1에 다음 책임을 분리한다.

- `releases`: 사용자에게 보여주는 정규화된 상품·발매 정보
- `release_channels`: 하나의 상품을 판매하는 판매처, 시간, 가격과 링크
- `release_sources`: 판매처별 마지막 성공·실패와 수집 통계
- `release_changes`: 날짜, 시간, 가격, 링크의 이전 값과 변경 시각
- `review_items`: 자동 확정할 수 없는 후보와 검수 상태
- `saved_releases`: 로그인한 사용자의 관심 일정

외부 원본 전체 HTML은 저장하지 않는다. 일정 판정에 필요한 정규화 값, 출처 URL, 수집 시각과 변경 이력만 보관한다.

## 중복 판정

중복은 다음 순서로 판정한다.

1. 같은 정규화 스타일 코드와 발매일
2. 같은 정규화 상품명·브랜드·발매일
3. 제목 유사도가 높고 브랜드·발매일이 같지만 스타일 코드가 없는 경우

1번과 2번은 자동 병합한다. 3번은 검수 후보로 보낸다. 병합 시 상품은 하나로 유지하고 판매처별 발매 채널을 추가한다. 국내 공식 발매와 해외 발매는 같은 상품이어도 별도 채널로 유지한다.

## 자동 공개와 검수 기준

다음 조건을 모두 만족하면 자동 공개한다.

- 공식 캘린더 또는 공식 판매처 상품 페이지
- 발매일 존재
- 상품 또는 일정 원본 링크 존재
- 제목이 비어 있지 않음

다음 경우만 검수함으로 보낸다.

- 동일 상품의 공식 출처 간 날짜·시간 충돌
- 스타일 코드 없이 유사 제목만으로 중복이 의심됨
- 협업 또는 래플로 분류됐지만 발매일이 없음
- 상품 링크가 없거나 판매처 도메인과 일치하지 않음

통합 사이트 한 곳에서만 발견된 일정은 낮은 신뢰도로 공개하되 출처를 명확히 표시한다. 날짜를 추정한 일정은 공개하지 않는다.

## 사용자 화면

기존 오늘·내일·월간 달력 구조를 유지한다.

- `전체`, `스니커즈`, `패션`, `라이프스타일`, `협업`, `래플` 필터
- 협업 일정의 `COLLAB` 배지
- 응모 일정의 `RAFFLE` 배지
- 오프라인 한정 일정의 `SEOUL ONLY` 배지
- 홈 화면의 `주목할 협업 발매` 영역
- 하나의 상품 카드 안에 여러 판매처 채널 표시
- 로그인 사용자의 관심 일정 저장과 `내 관심 발매` 모아보기
- 날짜·시간·가격이 바뀐 일정의 `일정 변경` 표시
- 공식 출처와 마지막 확인 시각 표시

검색과 필터는 이미 받은 D1 결과에 적용하며 외부 판매처 요청을 만들지 않는다.

## 관리자 화면

관리자 화면은 전체 일정을 반복 확인하는 도구가 아니라 예외 처리 도구다.

- 검수 후보 수와 사유
- `승인`, `수정`, `무시`, `병합`
- 변경 전 값과 후보 값 비교
- 판매처별 마지막 성공·실패 시각
- 원본 수, 신규 수, 병합 수, 검수 후보 수
- 실패한 판매처 한 곳만 수동 재수집
- 24시간 이상 정상 갱신되지 않은 판매처 경고

검수하지 않은 후보는 공개하지 않고 보관한다. 기존 공개 일정과 정상 데이터는 검수 지연의 영향을 받지 않는다.

## 오류 처리

- 판매처 타임아웃은 해당 판매처 실패로만 기록한다.
- 일부 판매처 실패는 전체 수집 작업을 실패시키지 않는다.
- 마지막 정상 수집 데이터는 새 성공 결과가 저장될 때까지 유지한다.
- 빈 응답이 오면 기존 데이터를 삭제하지 않는다.
- 한 판매처가 연속 세 번 실패하면 관리자 화면에 경고한다.
- 잘못 병합된 일정은 변경 이력과 채널 정보를 사용해 분리할 수 있다.

## 보안과 운영

- 예약 수집과 수동 재수집은 서버에서만 실행한다.
- 수동 재수집은 로그인한 관리자만 사용할 수 있다.
- 외부 HTML이나 SNS 이미지를 사이트 자산으로 무단 복제하지 않는다.
- 판매처별 요청 수는 예약 실행 횟수와 필요한 상세 요청으로 제한한다.
- 외부 요청에는 짧은 타임아웃과 식별 가능한 사용자 에이전트를 사용한다.

## 검증

- 각 신규 어댑터의 정상 응답, 빈 응답, 잘못된 날짜와 링크 테스트
- 스타일 코드 및 상품명 기반 중복 판정 테스트
- 변경 감지와 이전 값 보존 테스트
- 자동 공개와 검수함 분기 테스트
- 한 판매처 실패 시 다른 결과와 마지막 정상 데이터 유지 테스트
- 예약 수집 이외 사용자 요청에서 외부 `fetch`가 실행되지 않는지 테스트
- 전체·카테고리·협업·래플 필터 테스트
- 관심 일정의 사용자 소유권 테스트
- 관리자 권한과 수동 재수집 제한 테스트
- 데스크톱과 모바일의 달력·카드·검수함 확인
