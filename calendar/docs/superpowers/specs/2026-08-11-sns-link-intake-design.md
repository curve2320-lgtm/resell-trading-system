# SNS 원문 링크형 수집 설계

날짜: 2026-08-11
상태: 사용자 승인 범위 및 Grok·Claude Code 검토 반영

## 결정 요약

SNS v1은 공개 계정 전체 자동 크롤러가 아니라, 관리자만 공식 브랜드·리테일러 게시물의 원문 URL을 등록하는 수동 링크 수집으로 구현한다.

- 공개 카드의 `원 게시글 보기`는 원래 SNS 게시물로 바로 이동한다.
- 사진, 영상, 전체 캡션, 댓글, DM, 스토리, 개인 계정 데이터는 저장하거나 재게시하지 않는다.
- SNS 게시물은 구매 링크가 아니라 발매 공지의 출처 채널이다.
- 발매일이 명시되지 않았거나 모호하면 공개하지 않고 검수 상태로 둔다.
- Instagram HTML 수집, 로그인 세션 수집, 일반 공개 계정 대량 탐색은 구현하지 않는다.
- 추후 자동화는 소유자 또는 협업 매장이 공식 API 권한을 직접 연결한 경우에만 검토한다.

이 설계는 공개 게시물이라는 사실과 자동 수집·재게시 권한을 구분한다. Meta 약관은 사전 허가 없는 자동 수집을 제한하므로, 링크를 관리자에게 직접 제출받는 v1이 현재 배포 환경과 권한 범위에 가장 잘 맞는다. 이 문서는 법률 자문이 아니며, 플랫폼 약관과 개별 게시물의 권리 상태를 우선한다.

## 목표와 비목표

### 목표

1. 공식 계정의 발매 공지를 일정 카드에 보조 채널로 연결한다.
2. 사용자가 한 번의 클릭으로 원 게시물에 도달하게 한다.
3. 상품명, 브랜드, 발매일, 응모/드롭 유형, 공식 계정명, 원문 URL 등 최소 메타데이터만 보존한다.
4. 기존 상품·판매처 채널과 SNS 공지 채널을 하나의 상품 아래 안전하게 묶는다.
5. 관리자 입력 오류, 중복 URL, 날짜 불명확성을 기존 검수 흐름으로 처리한다.

### 비목표

- Instagram, X, Threads, TikTok 등 플랫폼의 전체 공개 피드 자동 수집
- 개인 계정, 댓글, DM, 스토리, 팔로워 그래프 수집
- 사진·영상·전체 캡션의 저장, 핫링크, 사이트 내 재생
- 이미지에서 날짜나 상품 정보를 추론하는 OCR/비전/LLM 자동 판정
- SNS 게시물을 판매처 링크로 사용하거나 SNS를 다중 판매처로 계산
- v1에서 Meta 앱 심사·Business Verification·OAuth 연동

## 선택지와 최종 선택

### A. 공식 API 자동화

공식 API는 약관·운영 측면에서 가장 정석이지만, 임의의 브랜드 공개 계정을 자유롭게 읽는 API가 아니다. Business/Creator 계정, 앱 권한, 토큰 운영, 경우에 따라 앱 검수와 비즈니스 검증이 필요하다. 사설 캘린더가 여러 브랜드의 계정 연결을 확보하기 전에는 비용 대비 수집 범위가 작다.

### B. 관리자 원문 URL 등록

관리자가 공식 게시물 URL과 일정 메타데이터를 입력하면 시스템이 URL·계정·날짜를 검증하고 기존 수집 모델로 저장한다. 자동 발견은 아니지만 추가 권한과 네트워크 수집이 없고, 실제로 가치 있는 게시물만 선택할 수 있다.

### C. 공개 HTML 크롤링

공개 계정 allowlist만 두더라도 로그인 벽, 429, HTML 구조 변경, 플랫폼 약관 문제가 남는다. 현재 프로젝트의 “로그인/세션 수집 금지”와도 충돌하므로 제품 기능으로 채택하지 않는다.

### D. 단계형 혼합

v1은 B로 시작하고, 수동 등록량과 중복 정확도를 측정한다. 이후 실제로 소유자 또는 협업 매장이 계정을 연결할 수 있고, Meta 권한 심사를 통과할 수 있을 때만 A를 같은 정규화 파이프라인에 연결한다. C는 단계형 계획에도 포함하지 않는다.

최종 선택은 D이며, 첫 구현은 B이다.

## 시스템 설계

### 1. 관리자 입력

기존 owner-only 관리자 화면에 SNS 등록 영역을 추가한다.

필수 입력:

- 원 게시물 URL
- 공식 계정명 또는 핸들
- 상품명/게시물 제목
- 브랜드
- 발매일 또는 날짜 미정 선택
- 게시물 유형: 발매, 응모, 재입고, 공지

선택 입력:

- 스타일 코드
- 기존 상품에 연결할 catalog ID
- 발매 시간
- 관리자 메모

계정 핸들은 자유 입력을 신뢰하지 않고 공식 계정 allowlist에서 선택한다. v1 allowlist는 코드 또는 배포 환경 설정으로 관리하며, 개인 계정을 허용하지 않는다.

### 2. URL 검증과 링크 역할 분리

SNS 링크는 판매처 링크와 별도의 정책을 사용한다.

- `safeRetailerUrl(productUrl)`: Nike, Shoeprize 등 구매/응모 판매처만 허용
- `safeAnnouncementUrl(sourceUrl)`: v1에서는 `instagram.com`, `www.instagram.com`의 `/p/<shortcode>/` 또는 `/reel/<id>/` 경로만 허용
- `instagram.com`은 `approvedRetailerHostnames`에 추가하지 않는다.
- SNS 링크의 추적 query parameter는 제거하고, 로그인/리디렉션 경로는 거부한다.
- SNS 원문 URL은 `sourceUrl`에만 저장한다.
- SNS 전용 일정의 `productUrl`은 `null`로 둔다. 원문 버튼은 별도의 `sourceUrl` 렌더링 경로를 사용한다.

현재 `CollectedRelease.productUrl` 타입이 필수이고, API 투영부가 두 URL에 동일한 판매처 sanitizer를 적용하므로 이 두 지점을 분리하는 변경이 필요하다. 기존 D1의 `product_url`과 `source_url` 컬럼은 nullable이므로 v1에서 별도 테이블은 만들지 않는다.

### 3. 정규화·중복·우선순위

- `sourceKey`: `sns`
- `externalId`: Instagram shortcode 또는 canonical post ID
- `retailer`: `SNS · @account` 표시용 값
- `sourceUrl`: 원 게시물 permalink
- `productUrl`: SNS 전용 일정은 `null`
- `releaseDate`: 명확한 날짜만 공개 파이프라인으로 전달

동일 URL은 `sourceKey + externalId`로 멱등 처리한다.

SNS는 “announcement” 우선순위로 분류한다.

`first_party retail > aggregator > SNS announcement`

- 스타일 코드와 날짜가 공식 판매처와 일치하면 하나의 상품에 SNS 채널만 추가한다.
- SNS 날짜가 공식 판매처와 다르면 공식 채널을 유지하고 SNS 쪽만 검수 또는 비권위 채널로 남긴다.
- SNS가 공식 판매처 채널을 삭제하거나 `conflicting_schedule`로 차단하지 않는다.
- SNS 채널은 `hasMultiRetailerConfirmation` 계산에서 제외한다.
- 스타일 코드가 없고 기존 상품과 확실히 매칭되지 않으면 자동 병합하지 않고 관리자 병합 검수로 보낸다.

### 4. 날짜 미정과 검수

“곧 공개”, “이번 주말”, 이미지 안에만 있는 날짜처럼 명확하지 않은 정보는 자동 공개하지 않는다.

- 날짜 있음: 정상 채널 생성
- 날짜 없음/모호함: `missing_date` 검수 payload 생성
- 잘못된 호스트/비공식 계정: 저장하지 않고 거부 또는 검수
- 스타일 코드 불일치: `possible_duplicate` 또는 관리자 병합 대기

날짜 미정 검수는 live `CollectedRelease`로 우회하지 않고, 기존 `review_items.payload_json`을 이용한다. 관리자가 날짜를 확정한 뒤에만 live 채널 쓰기를 수행한다.

### 5. 수집과 갱신

v1 SNS 경로에는 outbound fetch가 없다.

- 관리자 제출 시에만 정규화·검증한다.
- 기존 사이트의 2~3회 수집 슬롯이 실행되어도 SNS manual source는 네트워크 요청 없이 기존 메타데이터를 유지한다. SNS 게시물을 자동으로 다시 읽거나 링크 상태를 확인하지 않는다.
- 삭제 여부를 확인하기 위한 HEAD/GET도 v1에서는 하지 않는다. 비공식 HTML 수집과 구분하기 어렵고, 데이터 가치가 낮다.
- 삭제된 게시물은 사용자가 원문을 열 때 확인하게 두며, 일정이 지나면 기존 날짜 필터에서 자연스럽게 사라진다.
- 이후 공식 API 단계에서만 API 응답으로 link health와 새 게시물 목록을 갱신한다.

### 6. UI

- 카드에 `SNS` 배지와 공식 계정명을 표시한다.
- SNS-only 일정은 버튼을 `원 게시글 보기`로 표시한다.
- 판매처 채널이 함께 있으면 판매처 버튼을 기본 CTA로 유지하고 SNS 버튼은 보조 출처로 표시한다.
- SNS 사진, 영상, 전체 캡션 미리보기는 제공하지 않는다.
- 원문 확인을 위해 외부 링크로 이동한다는 점을 버튼 주변에 명확히 표시한다.

## 오류 처리와 보안

- 관리자 인증은 기존 admin API의 동일 출처·owner-only 경계를 재사용한다.
- 원문 URL은 HTTPS, 허용 host, 허용 path를 모두 검사한다.
- URL에 사용자명·비밀번호·비표준 포트·리디렉션 파라미터가 있으면 거부한다.
- 같은 게시물 재등록은 중복 생성 없이 기존 채널을 반환한다.
- SNS 데이터 오류가 공식 판매처 캐시를 삭제하지 않도록 sourceKey별 쓰기 경계를 둔다.
- `RELEASE_SNS_INTAKE=off` 플래그로 신규 입력과 공개 SNS 채널 투영을 즉시 차단할 수 있게 한다.
- 원 게시물 URL과 최소 메타데이터만 저장하며, raw HTML·이미지·영상·전체 캡션은 D1/R2에 저장하지 않는다.

## 테스트와 수용 기준

1. 올바른 공식 Instagram permalink가 등록되면 정확한 원문 URL로 이동한다.
2. `instagram.com`이 아닌 host, `/p/`·`/reel/`이 아닌 path, allowlist 밖의 계정은 거부된다.
3. SNS URL이 `productUrl`로 노출되지 않고, `sourceUrl` 전용 sanitizer를 통과한다.
4. 날짜 미정·모호한 날짜는 live 일정이 되지 않고 `missing_date` 검수 1건만 생성된다.
5. 같은 URL을 두 번 등록해도 채널이 하나만 생긴다.
6. 스타일 코드와 날짜가 같은 공식 일정이 있으면 상품 1개와 채널 2개가 된다.
7. SNS 날짜가 공식 판매처와 달라도 공식 판매처 일정은 삭제되거나 검수로 사라지지 않는다.
8. SNS 채널이 추가되어도 다중 판매처 확정 플래그가 잘못 켜지지 않는다.
9. 저장된 payload에 이미지 URL, 영상 URL, raw HTML, 전체 캡션이 없다.
10. SNS 입력 경로에서 `fetch`가 호출되지 않는다.
11. 비관리자 요청은 SNS 등록에 실패한다.
12. SNS 소스 실패가 기존 공식 일정 캐시를 삭제하지 않는다.

## 추후 공식 API 단계의 진입 조건

다음 조건을 모두 만족할 때만 별도 설계를 시작한다.

1. 수동 SNS 등록이 한 달 이상 지속되고 자동화할 만한 게시물량이 확인된다.
2. 소유자 또는 협업 매장이 Business/Creator 계정 권한 연결에 동의한다.
3. Meta 앱·Business Verification·App Review 가능성을 확인한다.
4. 수동 등록에서 스타일 코드·날짜 중복 병합 오류가 허용 수준 이하로 유지된다.

공식 API가 추가되더라도 동일한 정규화·검수·채널 우선순위를 재사용하며, public HTML crawler는 추가하지 않는다.

## 롤백

v1은 별도 스키마 마이그레이션 없이 기존 nullable URL 필드를 활용한다. SNS 입력 flag를 끄면 신규 등록만 차단하고 기존 공식 판매처 데이터에는 영향을 주지 않는다. SNS 채널 투영을 끄더라도 원문 메타데이터는 삭제하지 않는다.
