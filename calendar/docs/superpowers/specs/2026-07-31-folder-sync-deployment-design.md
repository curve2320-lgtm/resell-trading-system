# 폴더 기준 배포 동기화 설계

## 목표

현재 로컬 폴더의 발매달력 사이트를 기존 `DROPLOG CLASS` Sites 프로젝트에 그대로 반영한다. 이번 작업에서는 새로운 사용자 기능을 추가하지 않고, 로컬과 운영 환경의 차이만 제거한다.

## 범위

- 기존 운영 주소와 로그인·접근 권한을 유지한다.
- 로컬의 브랜딩, 오늘·내일 일정, 월간 달력, 검색, 일정 상세와 외부 발매정보 연결 구성을 반영한다.
- 현재 프로젝트의 Next.js 구조와 패키지 구성을 유지한다.
- 기능 업그레이드는 이번 배포에 포함하지 않는다.

## 배포 구조

기존 Sites 프로젝트 `DROPLOG CLASS`를 재사용한다. 로컬 소스를 배포 환경에 맞게 빌드하고, 검증된 결과만 새 사이트 버전으로 저장한 뒤 기존 운영 배포를 교체한다.

## 데이터 흐름

브라우저는 `/api/releases`를 호출하고, 서버는 데이터베이스와 외부 발매정보 소스의 결과를 취합·중복 제거해 오늘, 내일, 월간 달력 화면에 전달한다. 운영 환경에서도 현재 로컬과 같은 소스 활성화 규칙을 사용한다.

## 오류 처리

- 빌드 실패 시 운영 배포를 변경하지 않는다.
- 외부 소스 일부가 실패해도 나머지 연결 결과를 표시하는 기존 동작을 유지한다.
- 새 배포 상태가 성공으로 확인되기 전에는 완료로 간주하지 않는다.

## 검증

- 프로덕션 빌드 성공
- `/`와 `/calendar` 렌더링 확인
- 오늘·내일 일정 수와 자동 연결 상태 확인
- 검색과 날짜 선택 동작 확인
- 모바일과 데스크톱 레이아웃 확인
- 기존 로그인·접근 권한 유지 확인

## 후속 작업

배포 완료 후 Superpowers 절차를 사용해 기능 개선 후보를 별도로 검토한다. 후보는 사용자 효과, 데이터 신뢰도, 구현 난이도와 운영 위험을 기준으로 우선순위를 정하며 이번 동기화 배포와 섞지 않는다.
